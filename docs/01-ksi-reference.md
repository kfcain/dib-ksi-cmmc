# The KSI reference

Generated by `tools/gen-ksi-doc.mjs` from `ontology/ksi-catalog.json`. Do not edit by hand; edit the catalog and regenerate.

Catalog version `0.2.0`, dated `2026-07-26`. 64 key security indicators across 16 families.

The catalog protects one thing: the confidentiality of CUI. Levels decide which requirements apply (CMMC L1/L2/L3, unchanged). Classes decide how much proof (A cheapest, D deepest). Every KSI applies to any DIB organization whose scope includes it, at any size; the deployment profiles in `ontology/responsibility-patterns.json` decide who runs each one.

Each entry carries:

- **Statement** — what must be true.
- **CUI confidentiality** — how the KSI protects CUI from disclosure. Where a KSI is not a confidentiality control, the line says so instead of implying otherwise.
- **Classes / levels / 800-171 r2 mapping** — where it applies and what it satisfies. 44 KSIs map to 800-171 r2 requirements; the rest are unmapped by design (uplift or scope machinery).

**Uplift (13 KSIs).** Beyond the 800-171 confidentiality floor — availability, integrity, or program maturity. Never required below Class D, never affecting level compliance; reported for CR26/Class-C reciprocity. Marked ↑.

**Non-deferrable (10 KSIs).** Crown-jewel indicators flagged ◆. The flag is informational; exception eligibility binds at the requirement level per 32 CFR 170.21.
